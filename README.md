# РЕНТА — ритуальный салон

Сайт на Next.js + Go. Данные хранятся в PostgreSQL,
при первом запуске автоматически заполняются из `backend/data/*.json`.

## Запуск через Docker

```bash
docker compose up --build
```

Сайт: http://localhost:3000
Админка: http://localhost:3000/admin (потребует пароль)
API: http://localhost:8080/api/health

## Переменные окружения (backend), см. docker-compose.yml

Секреты (пароль админки, Telegram-токен и т.п.) задаются через `.env`-файл в
корне проекта, который **не коммитится в git**. Скопируйте `.env.example` в
`.env` и заполните значениями:
```bash
cp .env.example .env
```

- `ADMIN_PASSWORD` — пароль входа в админку. **Обязательно смените** значение по умолчанию перед реальным запуском.
- `ADMIN_SECRET` — секрет для подписи сессионной cookie. Смените на случайную строку.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — если заполнены, при каждой новой заявке в Telegram придёт уведомление. Оставьте пустыми, чтобы отключить.
  - Токен бота получаете у [@BotFather](https://t.me/BotFather) (`/newbot`).
  - Chat ID менеджера: он пишет что угодно новому боту, затем откройте `https://api.telegram.org/bot<TOKEN>/getUpdates` — в ответе будет `chat.id`.
- `DATABASE_URL` — необязательно, полная строка подключения к PostgreSQL (например `postgres://user:pass@host:5432/dbname?sslmode=disable`). Если не задана, собирается из `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` (см. docker-compose.yml).

## Запуск без Docker

Backend (потребуется локально запущенный PostgreSQL — переменные `POSTGRES_*` или `DATABASE_URL`):
```bash
cd backend
go mod tidy
go run .
```

Frontend:
```bash
cd frontend
npm install
npm run dev
```

## Что уже работает
- Услуги, товары (с загрузкой фото, переключателем «цена / по запросу», показом/скрытием), заявки, настройки — всё редактируется в админке.
- Админка закрыта паролем (простая сессионная авторизация, без ролей).
- Заявки сохраняются в базе и (при заполненных переменных) дублируются уведомлением в Telegram.
- У каждой услуги есть отдельная страница по адресу `/services/<slug>` с полями SEO title/description, которые можно менять в админке.
- Форма заявки требует согласия на обработку персональных данных и оферту (чекбоксы, ссылки на страницы `/privacy-policy` и `/oferta` — сейчас там текст-заглушка, нужно заменить на реальные юридические документы).
- Телефоны в списке заявок в админке по умолчанию скрыты (видны только начало и последние 4 символа), есть кнопка «Показать».

## Что ещё нужно сделать перед боевым запуском
- Заменить `ADMIN_PASSWORD` и `ADMIN_SECRET` в `.env` на реальные секреты (сейчас там значения по умолчанию, менять только в `.env`, не в docker-compose.yml).
- Вставить реальный текст политики обработки персональных данных и оферты на страницы `/privacy-policy` и `/oferta`.
- Настроить регулярное резервное копирование базы PostgreSQL (например, `pg_dump` на другой сервер/облако раз в неделю по cron).
- Подключить Яндекс.Метрику, если нужна реальная статистика посещений (сейчас на дашборде админки — заглушка).
- Подключить настоящую карту на странице контактов.
